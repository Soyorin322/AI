有，而且到 **2026 年**這個方向已經比前兩年成熟很多。你要找的其實可以拆成三個技術層：**Persona（人格）、Memory（記憶）、Skills（能力模組）**。我搜尋後，這三塊現在都已經有相當值得直接研究的開源專案。

我先給你結論：如果你的目標是做一個「長期存在、維持角色人格、能記得共同經歷、又能逐步增加能力」的虛擬角色，我會優先研究下面這幾個。

| 領域             | 最值得看                           | 用途                 |
| -------------- | ------------------------------ | ------------------ |
| 角色人格           | **PersonaForge**               | 長時間維持角色性格、不容易人格漂移  |
| 角色實作格式         | **SillyTavern Character Card** | 現成且成熟的角色描述格式       |
| 角色型記憶          | **RoleMemo / DualMem**         | 把「事實」與「角色主觀理解」分開   |
| 通用長期記憶         | **Mem0**                       | 高效率保存與搜尋長期記憶       |
| Stateful Agent | **Letta / MemGPT**             | Agent 自己管理自己的記憶與狀態 |
| 本地角色記憶         | **TeleMem**                    | 特別針對角色/NPC，而且可完全本地 |
| multimodal 記憶  | **PersonaVLM**                 | 圖像、對話等多模態長期記憶      |
| Skills 格式      | **Agent Skills / SKILL.md**    | 現在已經形成開放規格         |

下面是比較重要的發現。

---

# 1. 角色性格建立：現在已經不只是「寫一大段 system prompt」

我最推薦你先看 **PersonaForge**。

這是 2026 ACL Findings 的研究，專門研究：

> 如何讓 LLM 在長時間 role-playing 中保持 personality consistency。

它不只是把「個性」寫成：

```text
她個性內向
講話冷淡
其實很關心朋友
```

而是從心理學角度，把角色人格做成更結構化的系統，並測試：

* Personality Consistency
* Style Adherence
* Defense Mechanism
* Response Diversity
* 長對話人格漂移
* 被外部干擾後能不能恢復角色

而且它還特別比較了：

* Zero-shot persona
* Character-LLM
* Structured CoT
* RAG Persona
* RoleLLM
* Periodic Re-grounding
* Memory + Reflection

所以這其實非常符合你想做「真正像某個角色」，而不是單純 ChatGPT 加角色 prompt 的方向。([GitHub][1])

---

## 一個很重要的新概念：人格 ≠ 背景資料

這點對你的虛擬角色會非常重要。

現在比較好的研究通常會把：

```text
角色是誰
```

和：

```text
角色知道什麼
```

分開。

例如：

```text
Persona
├── values
├── personality traits
├── emotional tendencies
├── speech style
├── interpersonal behavior
├── likes/dislikes
└── defense mechanisms
```

另外才是：

```text
Knowledge
├── biography
├── relationships
├── past events
├── world knowledge
└── current situation
```

這樣模型比較不容易發生：

> 「知道這個角色很多設定」
>
> 但說話完全不像這個角色。

這其實就是目前很多 character bot 最大的問題。

---

# 2. 如果你要直接研究成熟角色格式：SillyTavern Character Card

SillyTavern 仍然是目前開源 AI role-play 生態裡非常值得看的專案。

它的角色不是單純一段 prompt，而是 Character Card：

```text
Character
├── Name
├── Description
├── Personality
├── Scenario
├── First Message
├── Example Dialogue
├── System Prompt
└── Lore / World Info
```

官方文件明確說明 Character Card 本質上就是一組控制 LLM 行為的 prompt，並可以加入背景、行為、說話風格、Scenario 等資料。([GitHub][2])

它另外還有：

* World Info
* RAG
* Persona
* group character
* summary memory
* scripting
* expression
* image generation

所以如果你要做自己的系統，我其實不建議完全自己發明角色格式。

可以直接參考：

```text
Character Card
+
PersonaForge style personality model
```

這會比從零開始穩很多。

---

# 3. 2026 我認為對「虛擬角色」最重要的研究：RoleMemo / DualMem

這個非常值得你看。

2026 年 5 月的新研究：

**From Facts to Insights: A Persona-Driven Dual Memory Framework and Dataset for Role-Playing Agents**

它指出現在很多 Memory 系統其實有一個根本問題：

> Memory 記住的是「客觀事實」，
> 但角色真正會記住的是「她怎麼理解這件事情」。

這兩個不是同一件事。([arXiv][3])

例如你跟角色一起彈鋼琴。

傳統 memory：

```text
2026/8/15
User practiced piano for 45 minutes.
User had difficulty playing measure 32.
```

但角色型 memory 可能還要多一層：

```text
Factual memory:
User practiced piano for 45 minutes.

Persona-conditioned insight:
She noticed that he kept retrying the difficult part
instead of giving up.

Emotional interpretation:
She feels quietly pleased but probably won't praise him directly.
```

這就是 DualMem 的核心：

```text
Memory
├── factual cognition
└── persona-conditioned insight
```

我認為這個概念**非常適合虛擬角色**。

因為角色不只是資料庫。

真正像人的地方是：

> 同一件事情，不同的人會記得不同的東西。

而 RoleMemo 正是在研究這個問題。([arXiv][3])

---

# 4. 記憶技術：Mem0 在 2026 又進化很多

Mem0 現在依然是非常值得研究的 memory layer。

而且它在 **2026 年 4 月**換了新的 memory algorithm。

目前它會使用：

```text
Memory extraction
      ↓
Entity linking
      ↓
Semantic retrieval
BM25 keyword retrieval
Entity matching
      ↓
multi-signal fusion
      ↓
Temporal reasoning
```

也就是不是只有 vector similarity。([GitHub][4])

特別是 Temporal Reasoning 很重要。

例如：

```text
2025:
User 喜歡 A

2026:
User 已經不喜歡 A，改喜歡 B
```

普通 vector DB 可能把兩個都搜出來。

而新的 memory system 要知道：

```text
目前狀態 = B
歷史狀態 = A
```

這對長期陪伴型角色非常重要。

---

# 5. Letta / MemGPT：如果你要讓角色「自己管理記憶」

Letta 是 MemGPT 的後續系統。

它的方向跟普通 RAG 不太一樣：

```text
普通 RAG

User
 ↓
搜尋 DB
 ↓
LLM
```

而 Letta 比較接近：

```text
Agent
├── working memory
├── long-term memory
├── memory management
├── tools
└── self-modification
```

Agent 本身被視為有 persistent state 的東西。([GitHub][5])

而且 Letta 現在已經把記憶甚至保存成類似：

```text
~/.letta/.../memory/
```

這種可持續存在的 Agent 記憶結構。([GitHub][6])

如果你的核心理念是：

> 「這個角色不是每次開程式重新建立，而是一直是同一個人。」

Letta 的 architecture 很值得研究。

---

# 6. 我反而很推薦你看 TeleMem

這是一個 **2026 年還非常新的專案**。

TeleMem 特別強調：

> character memory / role-play / companion AI / NPC

而且可以完全本地：

```text
Qwen
+
FAISS
+
local memory
```

不用 cloud。([GitHub][7])

更重要的是它直接做：

```text
character A memory
character B memory
character C memory
```

彼此隔離。

也就是：

```text
global memory
≠
character memory
```

這對未來如果你的系統不只一個角色，會非常重要。

它 2026-07 還在更新，所以不是停止維護的舊專案。([GitHub][7])

---

# 7. PersonaVLM：這可能和你未來「一起看動畫」直接相關

這個我特別標出來。

CVPR 2026 Highlight：

**PersonaVLM: Long-Term Personalized Multimodal LLMs**

它處理的是：

> 長期 + multimodal + persona。

它把 memory 分為：

```text
Core memory
Semantic memory
Episodic memory
Procedural memory
```

然後會從：

* 對話
* 圖像
* multimodal history

主動抽取資訊，形成 long-term memory。

這其實已經非常接近你之前提到的：

> 跟角色一起看動漫
> 跟角色一起彈鋼琴
> 角色看到 / 聽到正在發生什麼

也就是未來 architecture 不應該只考慮：

```text
text → LLM
```

而應該是：

```text
Audio
Video
Text
MIDI
      ↓
Perception
      ↓
Memory
      ↓
Persona
      ↓
Response
```

PersonaVLM 正好是可以參考的方向。

# 8. 還有一個很值得看的實際 Companion Engine

我還找到一個很貼近你的用途：

**eros-engine**

它自己定位就是：

> open-source engine for AI companions

而且專門處理：

```text
persistent memory
relationship state
structured user insight
persona consistency
```

甚至會維護一個多維度的 relationship state，而不是只把「關係很好」寫在 prompt。

例如你未來完全可以有：

```text
Relationship
├── familiarity
├── trust
├── affinity
├── respect
├── emotional closeness
└── conflict
```

而不是：

```text
Relationship = 好朋友
```

這種結構化 state 對長期虛擬角色會可靠很多。

# 9. Skills：現在 `SKILL.md` 已經不只是 Anthropic 自己的格式了

這部分變化其實非常大。

你之前研究的：

```text
SKILL.md
```

現在已經發展成：

**Agent Skills open specification**。

基本格式：

```text
my-skill/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

其中 `SKILL.md`：

```yaml
---
name: piano-listening
description: Listen to MIDI piano performances and comment on them.
---
```

下面再寫自然語言 instructions。

Agent Skills 官方規格甚至明確把它定位成：

> lightweight open format for extending AI agent capabilities.

而且可以一起帶：

* scripts
* documentation
* templates
* resources

不再只是 prompt。

---

# 10. Skills 格式已經開始成為實際生態

非常有意思的是，一篇 **2026-08-11** 才發布的研究：

**GitSkills: A Dataset of Agent Skills on GitHub**

統計 2026 年 7 月 GitHub：

> **3,797,117 個 SKILL.md**
>
> 分布在 **282,200 個 public repositories**

也就是短短幾個月，`SKILL.md` 已經不算是小眾 Anthropic 格式了。

所以你之前決定把自己的 SIwave knowledge 做成：

```text
SKILL.md
references/
tools/
```

這個方向其實是非常合理的。

同樣概念也可以直接移植到虛擬角色。

例如：

```text
skills/
│
├── piano-listening/
│   ├── SKILL.md
│   └── scripts/
│
├── anime-watching/
│   ├── SKILL.md
│   └── references/
│
├── japanese-conversation/
│   └── SKILL.md
│
├── calendar/
│   └── SKILL.md
│
└── web-search/
    └── SKILL.md
```

角色本身不用「天生會所有東西」。

而是：

```text
Character
    +
Skills
```

這正好符合你希望：

> 不需要無所不知
> 可以逐漸增加現實世界能力

的設計哲學。

# 11. 如果是我現在幫你設計整個虛擬角色，我會用這個架構

我會把系統拆成 **5 個完全不同的層級**：

```text
┌──────────────────────────────┐
│        Character Core        │
│ Personality / Values / Voice │
│ PersonaForge style           │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│          Knowledge           │
│ biography / anime canon      │
│ world lore / relationships   │
│ RAG                          │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│           Memory             │
│                              │
│ Core                         │
│ Semantic                     │
│ Episodic                     │
│ Persona-conditioned insight  │
│ Relationship state           │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│            Skills            │
│ SKILL.md                     │
│ piano / anime / web / etc.   │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│         Perception           │
│ microphone                   │
│ screen                       │
│ MIDI                         │
│ image / video                │
└──────────────────────────────┘
```

這樣你的「角色」就不是 LLM。

LLM 只是：

> **角色的大腦推理引擎之一。**

真正的角色是：

```text
Character =
Persona
+ Knowledge
+ Memory
+ Relationship
+ Skills
+ Perception
+ LLM
```

我認為這個理解非常重要。

## 我目前最推薦你研究的 GitHub 順序

如果你接下來真的準備開始做，我建議不要一次看二十個 repo。照這個順序：

1. **PersonaForge**
   → 研究「人格到底怎麼結構化」。

2. **SillyTavern Character Card / World Info**
   → 研究現有角色資料怎麼描述與注入 prompt。

3. **RoleMemo / DualMem**
   → 研究「角色自己的主觀記憶」。

4. **Mem0 + TeleMem**
   → 研究具體 memory storage / retrieval。

5. **PersonaVLM**
   → 之後做到一起看動畫/環境感知時再研究。

6. **Agent Skills specification**
   → 建立你的能力模組格式。

其中我認為 **RoleMemo / DualMem + PersonaForge** 是你之前規劃角色 AI 時還沒有納入、但現在非常值得加入的兩個新方向。

尤其 DualMem 的：

> 「角色記得的不只是發生什麼，而是她怎麼理解發生的事情」

我認為這很可能會成為你要做「擬人角色」時非常核心的一層。
